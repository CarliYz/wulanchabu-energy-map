# 乌兰察布能源地图决策分析平台

这是 Blender 地理模型的浏览器入口。页面加载 `assets/乌兰察布_真实地理场景_v2.glb`，把真实地理背景、A/B/C 农业设施、数据中心、能源枢纽和候选管线组织成白底极简的决策工作台。地图铺满工作区，实体索引、图层/详情和分析面板以浮动卡片叠加显示。

当前页面包括：

- 顶部项目、数据版本和工况状态；
- 左侧区域与设施树，点击后同步地图聚焦、对象高亮和右侧详情；
- 中央 Three.js 3D 地图，支持旋转、滚轮缩放和“小手平移”；
- 卫星地图 / 标准地图切换：标准地图加载带署名的 OpenStreetMap 白底导航瓦片，并叠加区域色块；卫星地图显示 GLB 中的 Sentinel-2 与 Copernicus DEM；
- 地形、能源设施、农业设施和供回管线图层开关；
- 对象详情卡、双击聚焦、复位视角和底部决策分析抽屉；
- 正常工况 / 源退出 / 储能耗尽（派生）切换，分析结果从本地 `analysis-results.json` 读取并通过 URL 的 `scenarioId` 恢复；
- 顶部审计入口，读取 `audit-manifest.json`，展示 Git、Blender、GLB、分析资产哈希、对象状态和工程边界，并支持导出审计 JSON；
- 59 个可拾取对象，状态标签区分已核验、候选和待核内容。

## 启动

在本目录的上一级工程目录运行：

```bash
python3 -m http.server 8766 --directory web/map-viewer
```

然后访问 `http://127.0.0.1:8766/`。也可以把 `8766` 换成其他空闲端口。直接双击 HTML 文件可能被浏览器的 `file://` 安全策略阻止模块或 GLB 加载。

Three.js、OrbitControls 和 GLTFLoader 从 jsDelivr 加载；页面通过 import map 统一解析 `three` 模块名，模型和业务数据仍保存在本地工程中。

## 交互验收

| 操作 | 结果 |
| --- | --- |
| 点击左侧实体 | 地图定位、树节点高亮、右侧详情同步 |
| 点击 3D 对象 | 显示对象详情并保留 selected/highlight 状态 |
| 双击对象或点击“聚焦此对象” | 相机移动到对象包围盒 |
| 点击小手 | 切换左键旋转 / 左键平移 |
| 拖动地图 | 平移当前底图位置 |
| 滚轮或点击放大 | 缩放地图 |
| 点击复位 | 恢复总览相机和默认详情状态 |
| 切换底图 / 图层 | 保留相机和选中对象，仅改变对应显示层；卫星与标准地图按钮互斥 |
| 收起 / 展开实体索引 | 默认显示窄列，展开后显示搜索、树状实体和状态标签 |
| 切换工况 | 更新顶部状态、地图底部说明、能量账、PTES 状态、推荐动作和逐时柱状图，并把 `scenarioId` 写入 URL |
| 展开决策分析 | 显示能量账、PTES 库存、推荐动作和 24 小时柱状图 |

## 工程边界

页面中的候选设施、候选管线、历史坐标和示意参数保留“候选 / 待核 / 方案展示”语义。当前线路用于表达方案关系，未表达管径、埋深、水力计算或工程施工定线。

## 决策分析数据边界

`assets/analysis-results.json` 是由 `data/generated/results.json` 导出的可追溯展示资产，包含 `MVP_NORMAL` 和 `MVP_SOURCE_OUTAGE` 两组 24 小时结果，以及输入与参数 SHA256。数据声明为 `synthetic teaching, no local operational validation`，用于演示页面的能量账和工况联动。

“储能耗尽（派生）”不会伪装成新的热力求解。页面从 `MVP_SOURCE_OUTAGE` 中定位首次 `storage_end_mwh <= 0` 的时段，并明确显示“派生分析”与对应时刻；当前资产中首次耗尽时段为 `h5`。

布局和回归约束见 `docs/QA_PLAN_UI_V2.md`。

审计入口不会把来源缺失伪装成已核验。当前标准地图使用 OpenStreetMap 标准瓦片并保留署名；若后续接入 Google Maps，需要补充 API key、版权标识、服务授权和三维相机同步验收。
